# Evidence

## Initial Findings

- EchoVault prior context says Codex Desktop `Continue` must stay distinct from `Resume` and uses `turn/start`.
- `graphify query` and targeted `rg` point to `apps/miniapp/src/index.ts` for the Mini App session-detail and `/new-task` form paths.
- Current session-detail follow-up links are generated by `renderSessionDetail`.
- Root cause: direct Mini App `userId` context was not preserved through session/project follow-up links and the `/new-task` success `sessionHref`, so direct-context submits could create work but navigate to a contextless detail route.

## Build Fix

- Added `userId` preservation to `/session/:id`, legacy `/?screen=session&id=...`, project follow-up links, and `/new-task` JSON success hrefs.
- Added regression coverage for session-detail question/task links and follow-up POST prompt context.
