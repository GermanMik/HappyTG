# HappyTG 0.4.30

HappyTG `0.4.30` fixes Codex Desktop session continuation from the Mini App and hardens host-proxy warmup for old Desktop sessions.

## Highlights

- `0.4.30`
- `/codex/desktop-continue` now returns a concrete `sessionHref` for the continued Desktop session.
- The Mini App continue form shows accepted feedback, restores its controls, clears the prompt, and navigates to newest history instead of blindly reloading.
- Codex Desktop control warmup now uses a `10000ms` timeout, matching the host-proxy request window.
- Default Desktop session list fetches get a `10000ms` startup budget while explicit `HAPPYTG_MINIAPP_CODEX_FETCH_TIMEOUT_MS` overrides remain respected.
- Live app-route smoke delivered a test prompt to old Desktop session `019ed3d8-904b-7eb0-97bd-1c10f09df378`.

## Safety Notes

- `Resume`, `Continue`, and `New Task` remain distinct actions.
- No policy, approval, Telegram transport, or host-daemon dispatch invariants were weakened.
- The live smoke used an isolated temporary API store with a non-secret smoke user and did not persist credentials.
