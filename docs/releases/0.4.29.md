# HappyTG 0.4.29

HappyTG `0.4.29` fixes Mini App follow-up submission from existing session pages opened with direct user context.

## Highlights

- `0.4.29`
- Session detail actions `Задать вопрос` and `Новая задача` now preserve direct `?userId=` context.
- Legacy `/?screen=session&id=...` detail entrypoints preserve the same follow-up context.
- Project and Desktop project follow-up links preserve direct context for new tasks and questions.
- `/new-task` success JSON now returns a context-preserving `sessionHref`, so the client navigates to the created session detail instead of losing auth context.
- Regression tests cover the session-detail follow-up link, form rendering, POST body, `Context session: <id>.` prompt prefix, and success href.

## Safety Notes

- No Codex Desktop mutation semantics changed.
- `Resume`, `Continue`, and `New Task` remain distinct actions.
- No policy, approval, Telegram transport, or host-daemon dispatch behavior changed.
- The fix preserves existing Mini App auth; it does not bypass session auth.
